# ADR-002: Cache successful endpoint responses

- **Status:** Accepted
- **Date:** 2026-11-19
- **Decision owner:** Grant Sarfo Darkwah

## Context

TMDb provides movie details and credits through separate endpoints. Repeated requests increase runtime and API usage.

## Decision

Cache successful raw responses separately for details and credits. Reuse cached responses on subsequent runs.

## Alternatives considered

### Alternative A: Fetch all responses on every run

- **How it would work:** Request details and credits for every valid ID each time.
- **Why it is attractive:** Always retrieves current API responses.
- **Why rejected:** Increases API usage and execution time.

## Consequences

- **What this buys:** Faster reruns and reproducible acquired inputs.
- **What this costs:** Cache storage and cache-management logic.
- **What it costs the client if I am wrong:** Cached data may become outdated.
- **What would make me revisit this:** A defined freshness requirement or a need to refresh source data.

## What this survives

- Quarterly reruns.
- Growth from 117 to 500 titles.
- Interrupted acquisition runs.


# ADR-004: Normalize analytical datasets and persist as Parquet

- **Status:** Accepted
- **Date:** 2026-11-19

## Context

TMDb details and credits responses contain film-level attributes and nested
one-to-many relationships. Flattening all fields into one table would
multiply film-level records and complicate analytical joins.

The transformation layer must produce reproducible datasets for downstream
analysis while preserving the original API responses.

## Decision

Transform successful cached details and credits responses into five
separate analytical datasets:

| Dataset | Grain | Key |
|---|---|---|
| films | One row per movie | movie_id |
| cast | One row per cast credit per movie | movie_id + credit_id |
| crew | One row per crew credit per movie | movie_id + credit_id |
| film_genres | One row per movie-genre association | movie_id + id |
| film_companies | One row per movie-company association | movie_id + id |

Persist the datasets as Parquet files in the `out/` directory.

Validate required tables, key completeness, uniqueness, and child-to-film
relationships before persistence.

Retain the raw API responses in their separate cache directories.

## Alternatives considered

### Alternative A: Store all attributes in one denormalized table

- **How it would work:** Expand cast, crew, genres, and companies into
  one combined film table.
- **Why rejected:** Multiple one-to-many relationships would multiply
  records and distort film-level analysis.

### Alternative B: Store only CSV files

- **How it would work:** Export each analytical dataset as CSV.
- **Why rejected:** Parquet provides typed, columnar storage suited to
  downstream pandas analysis.

## Consequences

- **What this buys:** Clear dataset grain, reproducible transformations,
  reliable joins, and efficient analytical storage.
- **What this costs:** Additional transformation, validation, and storage
  logic.
- **What it costs the client if I am wrong:** Incorrect joins or duplicated
  film records could distort licensing recommendations.
- **What would make me revisit this:** A change in analytical requirements,
  output consumers, or storage constraints.

## What this survives

- Growth from 112 successfully acquired films to 500 candidates.
- Quarterly reruns using cached API responses.
- Additional analytical relationships and downstream reporting.
